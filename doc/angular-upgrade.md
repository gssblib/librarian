# Angular 16 to 22

The staff and public frontends now use Angular 22.2.4, Angular CLI/Material
22.2.5, and TypeScript 6.0.3. Both frontends and the backend can use Node 24;
`client/.nvmrc` selects 24.22.1. Backend code, database schema, Firebase
configuration, and the existing build output directories are unchanged.

## Changes

Angular's required migrations were applied one major version at a time, from
17 through 22. They update template control flow, HTTP/bootstrap providers,
and explicit component metadata. The app retains NgModules, zone-based change
detection, and its prior TypeScript strictness settings. Optional architectural
and build-system migrations were not applied.

Compatible releases of Formly, the date picker, file upload, and PDF viewer are
pinned in the client manifest and lockfile. The discontinued Angular Flex Layout
package is replaced by `@ngbracket/ngx-layout`, retaining the existing directives.
The obsolete Codelyzer dependency and unused direct Terser dependency were
removed because they conflict with the newer toolchain. Karma was updated to
meet the Angular builder's peer requirement; the legacy unit tests were not
rewritten.

The theme uses the supported Material 2 theme definition, explicit typography
and density, and the original toolbar background. The PDF viewer now uses its
default browser-language behavior instead of the removed `useBrowserLocale`
input. Sass include paths allow the date-picker stylesheet to resolve with the
newer build tools.

The four tabbed page containers explicitly connect each Material navigation bar
to its content panel. This also removes the development-mode missing-panel error.

## Verification

From `tests/browser`, with Node 24 on PATH, run `npm test`. It compiles the
backend, builds both production frontends, and runs Chromium against a disposable
fictional MySQL database. See [test setup](../tests/browser/README.md).

Verified locally: a clean `npm ci`, `npm ls --all` without peer conflicts, both
production builds, and 19 passing workflow tests plus three reproduced known
failures. The test run cleaned up its disposable database afterward.

A separate development-server check against the existing local QA backend also
passed login, catalog and borrower browsing, and tab-panel rendering on the item,
borrower, administration, and reports pages. These checks did not edit QA records.

The suite covers the original workflows plus drag-and-drop cover upload and
rendering an existing PDF through the real API. The PDF fixture is generated by
the test harness; this does not exercise or repair the existing label-generation
problem. All database mutations in the suite stay in the disposable instance.

The desktop screenshot reference was reviewed and updated for small Material
table-height and icon differences. The deletion dialog and narrow-screen
reference images were retained. Existing narrow-screen clipping is not fixed by
this upgrade.

The two previously identified public-site bugs remain expected failures: the
loading state after an incorrect school password, and the server error when a
family places an order. Their fixes are deferred until after this upgrade.

## Extra review on November 3, 2026

Five additional checks cover borrower creation/editing, required fields and
dropdown persistence; calendar selection and fee calculation in a New York
timezone; administration tabs, file selection and canceled queue deletion;
order-cycle details and canceled deletion; and report filters, native date
inputs, reload persistence and CSV export contents.

The date/time pass uncovered another existing issue: the order-cycle forms refer
to an unregistered Formly `datetimepicker` type. A read-only comparison against
the local Angular 16.2.12 frontend reproduced the same missing-type errors and
absent inputs. It is recorded as a third expected failure, not repaired in this
upgrade. This limits confidence in order-cycle date editing specifically. The
working Material calendar and native report date inputs are covered separately.

The test fixture now catches Angular console errors as well as uncaught browser
errors. Angular's error handler can log a broken form without emitting an
uncaught browser exception.

Diff review found unchanged class bodies in all 84 modified application
TypeScript files, and identical expressions in all 88 migrated `ngIf` conditions.
Review of property/event bindings across 41 changed templates found only the
documented tab-panel, PDF locale, switch and optional-navigation migrations.
Bootstrap, theme, dependencies and compiler/build configuration changes were
also reviewed; no backend, schema or deployment configuration changes were found.

## Remaining tooling notices

The existing Webpack browser builder is deprecated but still works in Angular 22. Switching to the application builder can be a separate change. Existing
unused-entry-point/CommonJS warnings and the old Karma/Protractor scaffolding
remain outside this upgrade's scope.

The date-picker publisher marked 17.1.0 deprecated because its release number
should have been 18. At the time of this upgrade it is the published release
declaring Angular 22 compatibility, and no version 18 is published. This is a
dependency follow-up, not a reason to bypass peer checks.

No deployment is performed by any of the verification commands above. Review
and production deployment remain separate steps.
